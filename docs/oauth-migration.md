# Migrating from Passport to Provider-Neutral OAuth

This guide explains how to migrate an existing MBKAuthe application from legacy Passport strategies to the provider-neutral OAuth architecture in MBKAuthe v6.

---

## 1. Summary of Breaking Changes

| Feature | Legacy (v5 / Passport) | Modern (v6 / Provider-Neutral) |
|---|---|---|
| Core Engine | `passport` + `passport-*` | `mbkauthe/oauth` (zero dependencies) |
| Configuration | `passport.use(...)` / `process.env` | `createAuth({ oauth: { providers: [...] } })` |
| Token Verification | Hardcoded callback parsing | `jose` (JWKS discovery + signature validation) |
| PKCE | Optional / provider-specific | **Default-on S256** |
| State Storage | In-session cookie token | `OAuthStateStore` (TTL-bound, one-time consumption) |
| Token Storage | Plain text / unencrypted | **AES-256-GCM encrypted at rest** |
| Account Table | `mbkcore_user_github` / `mbkcore_user_google` | Unified `mbkcore_oauth_accounts` table |

---

## 2. Step-by-Step Migration

### Step 1: Remove Passport Middleware from `app.ts`

Remove Passport initialization calls:

```diff
- import passport from "passport";
  ...
  app.use(session(sessionConfig));
  app.use(sessionRestorationMiddleware);
- app.use(passport.initialize());
- app.use(passport.session());
  app.use(sessionCookieSyncMiddleware);
```

### Step 2: Update Provider Setup with `createAuth`

Replace ad-hoc passport configuration with declarative provider presets:

```typescript
import { createAuth } from "mbkauthe";
import { googleProvider, githubProvider } from "mbkauthe/oauth/presets";

export const auth = createAuth({
  appName: "Portal",
  oauth: {
    stateTtlSeconds: 600,
    allowAutoLinkByEmail: false,
    providers: [
      googleProvider({
        clientId: process.env.GOOGLE_CLIENT_ID!,
        clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
      }),
      githubProvider({
        clientId: process.env.GITHUB_CLIENT_ID!,
        clientSecret: process.env.GITHUB_CLIENT_SECRET!,
      }),
    ],
  },
});
```

### Step 3: Mount the OAuth Router

Mount the router generated by `createAuth`:

```typescript
import express from "express";
import { auth } from "./auth.js";

const app = express();

// Standard OAuth endpoints
app.use("/auth/oauth", auth.createOAuthRouter());
```

### Step 4: Run Database Migration

Apply the new `mbkcore_oauth_accounts` table to your database:

```sql
-- PostgreSQL
CREATE TABLE IF NOT EXISTS mbkcore_oauth_accounts (
    id integer GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    user_id character varying(50) NOT NULL REFERENCES mbkcore_users(username) ON DELETE CASCADE,
    provider_id character varying(50) NOT NULL,
    provider_user_id character varying(255) NOT NULL,
    profile jsonb DEFAULT '{}'::jsonb,
    access_token text,
    refresh_token text,
    id_token text,
    token_expires_at timestamp with time zone,
    scope text,
    created_at timestamp with time zone DEFAULT now(),
    updated_at timestamp with time zone DEFAULT now(),
    CONSTRAINT mbkcore_oauth_accounts_pkey PRIMARY KEY (id),
    CONSTRAINT uq_mbkcore_oauth_accounts_provider_user UNIQUE (provider_id, provider_user_id),
    CONSTRAINT uq_mbkcore_oauth_accounts_user_provider UNIQUE (user_id, provider_id)
);
CREATE INDEX IF NOT EXISTS idx_mbkcore_oauth_accounts_user_id ON mbkcore_oauth_accounts USING btree (user_id);
CREATE INDEX IF NOT EXISTS idx_mbkcore_oauth_accounts_provider_user ON mbkcore_oauth_accounts USING btree (provider_id, provider_user_id);
```

> [!NOTE]
> In MBKAuthe v6, social logins check `mbkcore_oauth_accounts` for linked accounts. If an account is not linked, login requests return a `${PROVIDER}_NOT_LINKED` error, ensuring explicit user linking and secure authentication.
